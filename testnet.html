Testnet Environment

Testnet

Use the Lombard testnet environment to safely reproduce and validate vulnerabilities before submitting reports. All testnet contracts mirror production logic but operate on test networks with no real funds at risk.

Testnet Not Covered Under Primacy of Impact

Testnet and mock contract deployments are not covered under Primacy of Impact. Bugs discovered on testnet environments must still correspond to vulnerabilities present in the mainnet production contracts to be eligible for rewards.

Testnet Environment Overview

Lombard maintains dedicated testnet deployments on Ethereum Sepolia and BNB Testnet. These environments are ideal for security researchers to reproduce potential vulnerabilities, build proof-of-concept exploits, and validate attack vectors without risking real funds.

The testnet contracts are deployed from the same codebase as the mainnet contracts. Any vulnerability discovered and reproduced on testnet that also affects mainnet production contracts will be treated as a valid mainnet submission, subject to the appropriate reward tier.

Lombard encourages all security researchers to use the testnet environment when developing PoC exploits. This helps demonstrate the vulnerability without needing to interact with live production funds.

How to Use the Testnet for Bug Bounty Research
1

Get Testnet Funds

Obtain test ETH from the Sepolia faucet or test BNB from the BNB Chapel faucet. No real funds are required for testnet testing. Links to recommended faucets are provided in the Documentation page.

2

Review Testnet Contract Addresses

Obtain the latest testnet contract addresses from the Smart Contracts page or directly from the GitHub repository. Addresses are listed per network in the deployment artifacts.

3

Reproduce the Vulnerability

Use Hardhat, Foundry, or another EVM testing framework to write and execute your proof-of-concept exploit. Confirm that the vulnerability is reproducible in a clean environment using the testnet contracts.

4

Verify the Same Code Exists on Mainnet

Before submitting, confirm that the affected code is also present in the mainnet production deployment. This is required for the report to be eligible for a reward. Cross-reference with audit reports to ensure the issue was not previously discovered.

5

Submit Your Report

Submit through the Immunefi dashboard. Include your testnet PoC transaction hashes, the corresponding mainnet contract addresses, and a clear explanation of the vulnerability's impact on production.

Testnet Limitations and Differences

Important: Testnet Rewards

Bugs found exclusively on testnet that do not affect mainnet production contracts are not eligible for bug bounty rewards. Testnet is provided solely as a safe environment for reproducing and validating vulnerabilities.

Known Differences Between Testnet and Mainnet

  • Testnet contracts may use mock oracles and simplified validator sets for easier testing
  • Babylon Bitcoin staking integration may be simulated with mock contracts on testnet
  • Testnet contract addresses differ from mainnet; always verify using the official sources
  • Gas prices and block times may differ from Ethereum mainnet behavior
  • Testnet contracts may be redeployed or upgraded more frequently than mainnet

What Cannot Be Tested on Testnet

  • Real BTC staking through Babylon (requires mainnet Bitcoin)
  • MEV and flashloan interactions with DeFi protocols (limited liquidity)
  • Governance attacks that depend on real token distribution
