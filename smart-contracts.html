Contract Overview

All Lombard Finance smart contracts are open source and available on GitHub. The contracts are written in Solidity and extensively tested with Hardhat and Foundry. Most core contracts are upgradeable using the OpenZeppelin TransparentUpgradeableProxy pattern.

Security researchers should pay particular attention to the proxy implementation contracts rather than the proxy contracts themselves, as vulnerabilities in the implementation logic are the primary security concern. The proxy admin and timelock contracts are also important vectors for governance attacks.

Contract Security Considerations

Upgrade Mechanism Risk

Most contracts use the OpenZeppelin TransparentUpgradeableProxy pattern. The ProxyAdmin contract controls all upgrades and is gated behind the Timelock. Storage layout collisions during upgrades are a key risk area to investigate.

Signature Verification

The Consortium Multisig uses off-chain signature aggregation. Review the on-chain signature verification logic for ECDSA malleability, replay attacks, and incorrect signer threshold validation.

Reentrancy

External calls during minting and redemption flows could enable reentrancy. Verify that the Checks-Effects-Interactions pattern is consistently applied or that ReentrancyGuard is used in all critical paths.

Integer Overflow

All contracts use Solidity 0.8+ with built-in overflow checking. However, unchecked blocks and custom math libraries may bypass these protections. Review yield calculation math carefully.

Audit History

Lombard has undergone multiple rounds of external security audits. All findings from these audits are considered known issues and are not eligible for bug bounty rewards. The full audit reports are available in the GitHub repository.

Audited Components

  • LBTC token contract and minting logic
  • Babylon integration and BTC staking flow
  • Cross-chain bridge contracts and LayerZero integration
  • Access control and governance mechanisms
  • Fee collection and distribution logic

Researchers are strongly encouraged to review all prior audit reports before submitting a bug report to avoid submitting already-known issues. Any unfixed vulnerabilities mentioned in the audit reports are also not eligible for rewards.
